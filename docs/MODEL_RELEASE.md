# Model artifacts and ONNX export

- Do **not** commit training-generated `.onnx`, `.pt`, `.pth`, TensorBoard logs, or large video files to the main source tree by default.
- Keep `scripts/export_policy.py`, the network definitions, package metadata and deployment schema versioned with the code.
- If real pretrained weights are released later, use a versioned release (or another persistent host) with SHA256 checksums, source commit, training config, normalizer, joint order, action scale, control frequency, robot firmware/SDK compatibility and a safety disclaimer.
- Export must include both **CAPE encoder** and **actor**. The surrogate dynamics and privileged training contact labels do not belong in the runtime inference graph.
- The synthetic checkpoint generated by `scripts/smoke_test.py` is **not a pretrained quadruped locomotion policy** and must not be used to drive motors.

Generate a TorchScript test artifact:

```bash
python scripts/smoke_test.py --config configs/mock_smoke.yaml
python scripts/export_policy.py --checkpoint outputs/mock_smoke/checkpoints/latest.pt --format torchscript --out outputs/mock_smoke/exported/policy.pt
```

Generate ONNX only after installing an ONNX export toolchain compatible with your local PyTorch release, and validate with ONNX Runtime against TorchScript outputs before deployment.
